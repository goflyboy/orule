## 7.0 本轮核心内容

部署视图描述系统在物理/容器/进程层面的部署形态，包括：

1. **进程拓扑**：本地 / 单机 / 容器 / K8s 四种部署形态
2. **网络端口与依赖**：服务间调用关系与端口分配
3. **制品与配置分发**：构建产物、配置、数据库迁移文件
4. **持久化布局**：本地文件 / Docker Volume / K8s PVC
5. **环境隔离**：dev / staging / prod 三环境差异
6. **升级与回滚**：灰度发布、版本管理

> 本章基于已定稿的技术模型（第 5 轮）和运行视图（第 6 轮）。

## 7.2 部署形态分类

### 7.2.1 形态 A：本地一体化（MVP / Phase 1）

> **用户决策**：Phase 1 不引入 Docker / K8s，本地一体化部署。

| 进程 | 运行方式 | 端口 |
|------|----------|------|
| orule-server | `java -jar orule-server.jar`（开发者机器本地） | 8080 |
| orule-runtime | `java -jar orule-runtime.jar` | 8081 |
| orule-web | `pnpm dev`（Vite 开发服务器） | 5173 |
| orule-llm-studio | 双击 `.app`（Electron 启动） | 5174（Local Server） |
| Cursor / OpenCode | 用户手动启动 | — |
| MySQL / PostgreSQL | Docker Desktop / 本地安装 | 3306 / 5432 |
| H2 | 文件模式 | — |

**优点**：简单、零依赖、易调试
**缺点**：仅适合单人开发 / Demo

---

### 7.2.2 形态 B：Docker Compose（开发联调 / 小团队）

> 二期支持。用于 3~5 人团队联调，引入容器化。

```yaml
# docker-compose.yml
version: '3.9'
services:
  orule-mysql:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: orule_root
      MYSQL_DATABASE: orule
    volumes:
      - mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping"]
      interval: 10s

  orule-server:
    image: orule/server:latest
    ports:
      - "8080:8080"
    depends_on:
      orule-mysql:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: docker
      ORULE_DB_URL: jdbc:mysql://orule-mysql:3306/orule
      ORULE_STORAGE_TYPE: local
      ORULE_STORAGE_LOCAL_BASE_PATH: /var/orule/artifacts
    volumes:
      - artifacts_data:/var/orule/artifacts
      - ./config/orule-server:/app/config
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 30s

  orule-runtime:
    image: orule/runtime:latest
    ports:
      - "8081:8081"
    depends_on:
      - orule-server
    environment:
      SPRING_PROFILES_ACTIVE: docker
      ORULE_SERVER_URL: http://orule-server:8080
    volumes:
      - ./config/orule-runtime:/app/config
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8081/actuator/health"]
      interval: 30s

  orule-web:
    image: orule/web:latest
    ports:
      - "5173:80"
    depends_on:
      - orule-server

volumes:
  mysql_data:
  artifacts_data:
```

    name: orule-server
  profiles:
    active: dev   # MVP 默认 dev

    url: jdbc:h2:file:~/orule/data/db/orule;AUTO_SERVER=TRUE

  storage:
    type: local   # local（默认）| s3 | oss | minio

logging:
  pattern:
    console: '{"time":"%d{yyyy-MM-dd HH:mm:ss.SSS}","level":"%level","service":"${spring.application.name}","traceId":"%X{traceId:-}","msg":"%msg"}%n'

## 7.6 环境隔离

### 7.6.1 三环境差异

| 维度 | dev（开发） | staging（预发） | prod（生产） |
|------|------------|-----------------|--------------|
| 数据库 | H2 文件模式 | MySQL（Docker） | MySQL（K8s StatefulSet） |
| LLM | Cursor/OpenCode 本地 Agent | 远程 LLM API（测试 key） | 远程 LLM API（生产 key） |
| ArtifactStorage | 本地文件系统 | 本地文件系统 | S3 / OSS |
| 端口 | 8080/8081 | 9080/9081 | 80/443（Ingress） |
| 日志级别 | DEBUG | INFO | WARN |
| 监控 | Console | Prometheus + Grafana | Prometheus + Grafana + 告警 |
| 数据来源 | 种子数据 | 脱敏生产数据 | 真实数据 |
| 部署方式 | 本地一体化 | Docker Compose | Kubernetes |
| 域名 | localhost | staging.orule.example.com | orule.example.com |
| 鉴权 | 无 | JWT（dev key） | JWT + OAuth2 |
| 限流 | 无 | 100 req/s | 1000 req/s |

### 7.6.2 Profile 切换

```bash
# 本地开发
java -jar orule-server.jar --spring.profiles.active=dev

# Docker Compose
java -jar orule-server.jar --spring.profiles.active=docker

# 生产
java -jar orule-server.jar --spring.profiles.active=prod
```

## 7.7 升级与回滚

### 7.7.1 版本号策略（SemVer）

```
主版本号.次版本号.修订号
  │         │         │
  │         │         └── Bug 修复（向后兼容）
  │         └──────────── 新功能（向后兼容）
  └────────────────────── 重大变更（不兼容）
```

示例：
- `1.0.0` → MVP 首版
- `1.1.0` → 新增功能（如 cruleengine 适配器）
- `1.1.1` → Bug 修复
- `2.0.0` → 破坏性变更（如 ArtifactStorage 接口大改）

### 7.7.2 数据库迁移（Flyway）

> **强约束**：每次 schema 变更必须新增 Flyway migration 文件，**不允许修改已有 migration**。

```bash
# 新增字段示例
# V6__add_rule_test_case_priority.sql
ALTER TABLE rule_test_case ADD COLUMN priority INT DEFAULT 0;
```

**回滚策略**：

| 场景 | 回滚方式 |
|------|----------|
| 应用 Bug | 回滚 JAR（K8s `kubectl rollout undo`） |
| 数据库迁移错误 | Flyway 自动检测版本不匹配，启动失败；人工修复或回滚 DB |
| 数据损坏 | 从备份恢复（每日全量 + 每小时增量） |

### 7.7.3 灰度发布（生产）

```
阶段 1：内部灰度（5% 流量）
  └─ K8s Deployment 灰度发布，仅内部员工可用

阶段 2：Beta 用户（20% 流量）
  └─ 通过 Ingress 按用户 ID 分流

阶段 3：全量发布（100% 流量）
  └─ 验证通过后，Deployment 副本数 = 全部

回滚：kubectl rollout undo deployment/orule-server
```

### 7.7.4 零停机升级

```
K8s 滚动升级（Rolling Update）：
┌────────────────────┐         ┌────────────────────┐
│ orule-server v1.0  │  v1.0   │ orule-server v1.0  │
│ replicas: 2        │ ──────▶ │ replicas: 1        │
│                    │  流量切换 │ + orule-server v1.1 │
└────────────────────┘         │ replicas: 1        │
                                └────────────────────┘

过程：
1. 新 Pod v1.1 启动
2. K8s 等待 health check 通过
3. 把流量从 v1.0 Pod A 切到 v1.1 Pod
4. v1.0 Pod A 优雅停机（处理完当前请求）
5. 重复上述步骤升级 v1.0 Pod B
6. 升级完成
```

| 数据库连接耗尽 | `hikaricp_connections_active == hikaricp_connections_max` | PagerDuty |
