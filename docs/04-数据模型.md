| 变更 | 原方案 | 更新方案 | 来源 |

| 规则域结构 | `Rule` / `RuleVersion` | `RuleSet` / `Rule` / `RuleArtifact` / `RuleSetArtifact` / `RuleTestCase` | 用户决策 + RFC-0008 |
| 编译产物落库 | 内存缓存 | **`compiledGroovy` 等编译产物落库**（RuleArtifact） | 用户决策 |

| **`attribute_type.data_type`** | `'string' | 'number' | ... | 'enumRef'` | kind 标签：`primitive / enum / object / list / map` | RFC-0031 |
| **`attribute_type.type_json`** | 不存在 | 新增 JSON 列，存储完整 Type 树 | RFC-0031 |
| **`function_lib.signature`** | VARCHAR(500) 字符串 | JSON（FunctionSignature：params + return） | RFC-0031 |
| `owner_code` 校验 | 未明确 | **强制校验** ObjectType 存在 | Q17 |
| `artifact_uri` | 未明确 | 存**相对 URL**；全局根路径拼接 | Q18 |
| `RuleSetArtifact` | 未明确 | **MVP 需要做** | Q19 |
| `code1..code5` | 5 个固定占位 | 保持占位；`DomainType.RuleForm` 配置决定启用哪些字段 | Q16 |

## 4.1 整体 ER 图（概念层）

```
DomainType（元数据类型）
├── ObjectType（业务对象）
│   └── AttributeType（字段类型）
├── EnumType（枚举类型）
├── FunctionLib（函数库）
└── RuleForm（允许的形态配置）

RuleSet（规则集）
├── name / code
├── domainTypeId → DomainType
└── Rule[]
    ├── RuleSet（维护态）
    │   ├── codeNSOrg（原始自然语言，RuleRepr）
    │   ├── codeSemantic（SimpleTS 源码，RuleSemantic）
    │   ├── code1..N（扩展形态占位；由 DomainType.RuleForm 配置决定启用哪些字段）
    │   └── ownerCode → ObjectType（规则归属）
    ├── RuleArtifact[]（发布态）
    │   ├── engineType（groovy / cruleengine）
    │   ├── compiledCode（编译产物，如 Groovy 脚本）
    │   └── version（制品版本）
    └── RuleTestCase[]（测试用例）
        ├── inputJson（输入事实）
        └── expectedOutput（期望输出）

RuleSetArtifact（规则集发布态）
├── ruleSetId → RuleSet
├── ruleArtifactIds[] → RuleArtifact[]
├── artifactType（JAVA_JAR / JS_BUNDLE / RULE_ENGINE_PACKAGE）
└── artifactUri（相对 URL；全局配置根路径拼接为完整路径）
```

## 4.2 元数据域（DomainType / ObjectType / AttributeType / EnumType / FunctionLib）

### 4.2.1 ER 图（RFC-0031 重构版）

```
DomainType
├── id (PK)
├── code (UK)
├── name
├── description
└── ObjectType[]
    ├── id (PK)
    ├── domainTypeId (FK → DomainType)
    ├── code
    ├── name
    └── AttributeType[]
        ├── id (PK)
        ├── objectTypeId (FK → ObjectType)
        ├── code
        ├── name
        ├── dataType（primitive / enum / object / list / map — kind 标签）
        ├── typeJson（JSON 树：完整 Type 结构）
        ├── nullable（默认 true）
        └── writable（默认 true；false 表示只读字段）

FunctionLib（与 DomainType 平行）
├── id (PK)
├── code (UK)
├── name
├── signature（JSON：FunctionSignature = params[] + returnType）
├── description
└── category

（注：`enum_type` 与 `enum_value` 表已删除，enum 定义内联到 `AttributeType.typeJson` 中）
```

## 4.3 规则域（RuleSet / Rule / RuleArtifact / RuleSetArtifact）

### 4.3.1 设计原则

继承 RFC-0008 的三层结构：

```
RuleRepr[]（表现层）   ← codeNSOrg（原始自然语言）
RuleSemantic（语义层） ← codeSemantic（SimpleTS 源码）
RuleExecution[]（执行层）← RuleArtifact（编译产物）
```

- **维护态**：业务人员/工程师看到的版本（codeNSOrg + codeSemantic + code1..code5）
- **发布态**：引擎实际执行的版本（RuleArtifact，编译产物落库）
- **规则集发布态**：多条规则打包后的产物（RuleSetArtifact）

### 4.3.2 ER 图

```
RuleSet（规则集）
├── id (PK)
├── code (UK)
├── name
├── domainTypeId → DomainType
├── ownerCode → ObjectType.code（规则归属）
├── status（DRAFT / PUBLISHED）
└── Rule[]
    ├── id (PK)
    ├── ruleSetId (FK → RuleSet)
    ├── code
    ├── name
    ├── ownerCode → ObjectType.code（**强制校验存在**）
    ├── ruleType（ATOMIC / COMPOSITE）
    ├── compositeType（当 ruleType=COMPOSITE 时）
    └── RuleVersion[]
        ├── id (PK)
        ├── ruleId (FK → Rule)
        ├── version (INT，自增)
        ├── codeNSOrg（原始自然语言，RuleRepr）
        ├── codeSemantic（SimpleTS 源码，RuleSemantic）
        ├── code1..code5（扩展形态占位）
        ├── tsAst（运行期 IR JSON）
        ├── llmGenerated（是否 LLM 生成）
        ├── validationStatus（VALID / INVALID / PENDING）
        ├── validationErrors（JSON）
        └── createdAt

    ├── RuleArtifact[]（发布态）
    │   ├── id (PK)
    │   ├── ruleId (FK → Rule)
    │   ├── ruleVersionId (FK → RuleVersion)
    │   ├── engineType（groovy / cruleengine / js）
    │   ├── compiledCode（编译产物，如 Groovy 脚本）
    │   ├── artifactVersion
    │   └── status（ACTIVE / DEPRECATED）

    └── RuleTestCase[]（测试用例）
        ├── id (PK)
        ├── ruleId (FK → Rule)
        ├── inputJson（输入事实）
        └── expectedOutput（期望输出）

RuleSetArtifact（规则集发布态）
├── id (PK)
├── ruleSetId → RuleSet
├── ruleArtifactIds[]（JSON，制品 ID 列表）
├── artifactType（JAVA_JAR / JS_BUNDLE / RULE_ENGINE_PACKAGE）
├── artifactUri（相对 URL；全局根路径拼接）
└── artifactVersion
```

## 4.4 运行时实例域（ObjectInst / RuleExecutor）

### 4.4.1 设计背景

元数据层（DomainType / ObjectType / AttributeType）定义的是**静态结构**（"Customer 是什么"），
运行时实例层（ObjectInst）承载的是**动态数据**（"这个具体的客户对象"）。

```
元数据层（编译期）                    运行时实例层（执行期）
─────────────────                  ─────────────────────
DomainType                         （无对应表，按需构造）
ObjectType ──────────────────────→ ObjectInst（运行时对象实例）
AttributeType                      ObjectInstField（属性值）
EnumType ────────────────────────→ EnumValue（枚举值实例）
```

**ObjectInst 与 ObjectType 的关系**：
- ObjectType 是"类"（模板），定义有哪些字段、字段类型
- ObjectInst 是"实例"（对象），承载具体业务数据
- ObjectInst 的结构必须符合其引用的 ObjectType 的定义

### 4.4.2 ObjectInst 模型（Java）

```java
package com.orule.common.model.instance;

/**
 * 运行时对象实例。
 * 对应元数据层的 ObjectType，是规则执行时的输入/输出数据载体。
 *
 * <p>ObjectInst 不落库 —— 它是方法参数，由调用方在内存中构造后传入 RuleExecutor。
 * 规则执行过程中的中间状态也用 ObjectInst 表示。
 */
public class ObjectInst {

    /** 实例 ID（UUID），用于追踪和调试 */
    private final String id;

    /** 引用的 ObjectType.programCode，如 "Customer"、"Order" */
    private final String objectTypeCode;

    /** 属性值 map：fieldName → value */
    private final Map<String, Object> fields;

    /** 元数据引用（可选，用于类型校验） */
    private final ObjectType objectType;

    public ObjectInst(String id, String objectTypeCode, Map<String, Object> fields, ObjectType objectType) {
        this.id = id;
        this.objectTypeCode = objectTypeCode;
        this.fields = new HashMap<>(fields);
        this.objectType = objectType;
    }

    /** 获取属性值 */
    @SuppressWarnings("unchecked")
    public <T> T get(String fieldName) {
        return (T) fields.get(fieldName);
    }

    /** 设置属性值 */
    public void set(String fieldName, Object value) {
        fields.put(fieldName, value);
    }

    /** 获取所有属性 */
    public Map<String, Object> getFields() {
        return Collections.unmodifiableMap(fields);
    }

    /** 转为 JSON（用于日志/持久化） */
    public Map<String, Object> toJson() {
        Map<String, Object> json = new LinkedHashMap<>();
        json.put("_id", id);
        json.put("_type", objectTypeCode);
        json.putAll(fields);
        return json;
    }
}
```

### 4.4.3 RuleExecutor 规则执行器

**RuleExecutor** 是规则执行入口，负责：
1. 根据 ruleId 加载规则制品（RuleArtifact）
2. 接收运行时上下文（Map<String, ObjectInst>）
3. 执行 Groovy 脚本
4. 返回执行结果

```java
package com.orule.runtime;

/**
 * 规则执行器。
 * 负责单条规则的执行，是 orule-runtime 模块的核心入口。
 *
 * <p>执行流程：
 * <ol>
 *   <li>根据 ruleId 加载 RuleArtifact（含 compiledGroovy）</li>
 *   <li>接收 inputContext（Map<String, ObjectInst>）</li>
 *   <li>初始化 Groovy 沙箱（RFC-0020）</li>
 *   <li>执行 Groovy 脚本</li>
 *   <li>从 outputContext 提取变更，写入 Execution 表</li>
 *   <li>返回 ExecutionResult</li>
 * </ol>
 */
public class RuleExecutor {

    private final RuleArtifactRepository artifactRepo;
    private final ExecutionRepository executionRepo;
    private final GroovySandbox sandbox;

    /**
     * 执行单条规则。
     *
     * @param ruleId        规则 ID
     * @param inputContext  输入上下文（变量名 → ObjectInst）
     * @return 执行结果
     */
    public ExecutionResult executeRule(String ruleId, Map<String, ObjectInst> inputContext) {
        long startMs = System.currentTimeMillis();
        String traceId = UUID.randomUUID().toString();

        // 1. 加载制品
        RuleArtifact artifact = artifactRepo.findActiveByRuleId(ruleId)
            .orElseThrow(() -> new RuleNotFoundException(ruleId));

        // 2. 构建执行上下文（ObjectInst → Groovy 可识别的 Map）
        Map<String, Object> groovyContext = buildGroovyContext(inputContext);

        try {
            // 3. 执行 Groovy 沙箱
            GroovyResult groovyResult = sandbox.execute(artifact.getCompiledCode(), groovyContext);

            // 4. 从 Groovy 结果提取 outputContext
            Map<String, ObjectInst> outputContext = extractOutputContext(
                groovyResult.getContext(), inputContext.keySet());

            // 5. 记录执行日志
            long elapsedMs = System.currentTimeMillis() - startMs;
            Execution execution = recordExecution(ruleId, artifact.getId(), inputContext,
                outputContext, groovyResult, elapsedMs, traceId, ExecutionStatus.SUCCESS);

            return ExecutionResult.success(execution.getId(), outputContext, elapsedMs, traceId);

        } catch (GroovyExecutionException e) {
            // 执行异常
            long elapsedMs = System.currentTimeMillis() - startMs;
            Execution execution = recordError(ruleId, artifact.getId(), inputContext,
                e, traceId, elapsedMs);
            return ExecutionResult.failure(execution.getId(), e.getMessage(), traceId, elapsedMs);
        }
    }

    /**
     * 批量执行规则（可选扩展，由 RuleSetArtifact.concurrency 控制）。
     */
    public List<ExecutionResult> executeBatch(String ruleSetId, List<Map<String, ObjectInst>> batchInput) {
        // 由 BatchExecutionService 调用（ADR-010）
        return batchInput.stream()
            .map(ctx -> executeRule(findFirstRuleOfSet(ruleSetId), ctx))
            .toList();
    }

    private Map<String, Object> buildGroovyContext(Map<String, ObjectInst> inputContext) {
        Map<String, Object> ctx = new LinkedHashMap<>();
        for (Map.Entry<String, ObjectInst> entry : inputContext.entrySet()) {
            ctx.put(entry.getKey(), entry.getValue().toJson());
        }
        return ctx;
    }

    private Map<String, ObjectInst> extractOutputContext(
            Map<String, Object> groovyContext, Set<String> varNames) {
        // 从 Groovy 执行结果中提取被修改的 ObjectInst
        // 规则只能修改 context 中已声明的变量
        Map<String, ObjectInst> output = new LinkedHashMap<>();
        for (String varName : varNames) {
            Object inst = groovyContext.get(varName);
            if (inst instanceof Map) {
                @SuppressWarnings("unchecked")
                Map<String, Object> json = (Map<String, Object>) inst;
                String id = (String) json.get("_id");
                String typeCode = (String) json.get("_type");
                json.remove("_id");
                json.remove("_type");
                output.put(varName, new ObjectInst(id, typeCode, json, null));
            }
        }
        return output;
    }

    private Execution recordExecution(String ruleId, String artifactId,
```

### 4.4.4 ExecutionResult 执行结果

```java
package com.orule.runtime;

import java.util.Map;

/**
 * 规则执行结果。
 * @param success    是否成功
 * @param executionId 执行记录 ID（可用于审计）
 * @param outputContext 输出上下文（规则执行后各变量的值）
 * @param elapsedMs  执行耗时（毫秒）
 * @param traceId    追踪 ID（用于日志关联）
 * @param errorMessage 错误信息（仅失败时）
 */
public record ExecutionResult(
    boolean success,
    String executionId,
    Map<String, ObjectInst> outputContext,
    long elapsedMs,
    String traceId,
    String errorMessage
) {
    public static ExecutionResult success(String executionId,
            Map<String, ObjectInst> outputContext, long elapsedMs, String traceId) {
        return new ExecutionResult(true, executionId, outputContext, elapsedMs, traceId, null);
    }

    public static ExecutionResult failure(String executionId,
            String errorMessage, String traceId, long elapsedMs) {
        return new ExecutionResult(false, executionId, null, elapsedMs, traceId, errorMessage);
    }
}
```

### 4.4.5 使用示例

```java
// 1. 构造运行时实例（来自业务系统，如数据库查询、API 调用）
Customer customer = new Customer();

Order order = new Order();

    "rule_vip_200_30",                          // 规则 ID
    Map.of("customer", customerInst, "order", orderInst)  // 输入上下文
);

// 4. 处理结果
if (result.success()) {
    Map<String, ObjectInst> output = result.outputContext();
    ObjectInst updatedOrder = output.get("order");
    BigDecimal discount = updatedOrder.get("discount");
    System.out.println("计算后的折扣: " + discount);  // 输出: 30
```

## 4.6 多版本策略与软删除

### 4.6.1 多版本策略

- **每保存一次生成新版本**：`rule_version.version` 自增
- `rule.current_version_id` 指向当前生效版本
- 历史版本**永久保留**，不做自动清理
- MVP 无版本数上限

### 4.6.2 软删除

| 表 | 删除策略 |
|----|----------|
| `rule_set` | 软删除（`deleted_at`） |
| `rule` | 软删除（`deleted_at`） |
| `rule_version` | 不允许删除（immutable） |
| `rule_artifact` | 标记 `status=DEPRECATED` |
| `execution` | 不允许删除（审计事实） |

## 4.9 DomainType 持久化映射（拼装 DomainMeta）

`DomainMeta`（SimpleTS 编译所需的元数据）由以下表拼装：

```java
public class DomainMeta {
    String id;                                    // → domain_type.code
    List<EnumType> enums;                         // → enum_type
    List<ObjectTypeDef> entities;                  // → object_type + attribute_type
    List<ContextVar> context;                     // 由 domain_type 配置的入口变量
}

// 拼装逻辑（在 RuleService 中实现）
DomainMeta buildMeta(String domainTypeId) {
    DomainType dt = domainTypeRepo.findById(domainTypeId);
    List<ObjectType> objects = objectTypeRepo.findByDomainTypeId(domainTypeId);
    return DomainMeta.builder()
        .id(dt.getCode())
        .enums(enumTypeRepo.findByDomainTypeId(domainTypeId).stream().map(...))
        .entities(objects.stream().map(obj ->
            ObjectTypeDef.builder()
                .id(obj.getCode())
                .fields(attributeTypeRepo.findByObjectTypeId(obj.getId()).stream().map(...))
                .build()
        ).toList())
        .context(buildContextVars(domainTypeId))
        .build();
}
```

## 4.10 Skill UI 嵌入设计（前端）

### 4.9.1 设计背景

MVP 阶段不使用独立 Skill 服务。Skill 能力通过 **前端 MCP Client** 直接调用 LLM 实现。

### 4.9.2 UI 嵌入卡片设计

规则编辑器中嵌入 Skill 调用卡片：

```
┌──────────────────────────────────────────────────────────────┐
│  规则编辑器                                                    │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │  [SimpleTS 源码]  │  [自然语言]  │  [表格]  │ [JSON]  │  ← 切换开关
│  └─────────────────────────────────────────────────────────┘ │
│                                                              │
│  ┌──────────────────────┐  ┌─────────────────────────────┐ │
│  │  SimpleTS 源码编辑器   │  │  🔄 Skill 调用卡片           │ │
│  │  textarea            │  │                             │ │
│  │                       │  │  输入：NL 描述              │ │
│  │  if (customer.tier   │  │  → [生成 SimpleTS] 按钮     │ │
│  │   == CustomerTier.VIP │  │                             │ │
│  │   && order.amount     │  │  或                         │ │
│  │   >= 200) {           │  │  输入：SimpleTS             │ │
│  │    order.discount=30  │  │  → [生成自然语言] 按钮      │ │
│  │  }                    │  │                             │ │
│  └──────────────────────┘  └─────────────────────────────┘ │
│                                                              │
│  [保存]  [执行测试]  [查看制品]                                │
└──────────────────────────────────────────────────────────────┘
```

**关键设计点**：
- **切换开关**：四视图（SimpleTS / 自然语言 / 表格 / JSON）通过 Tab 切换，**内容同步**
- **Skill 调用卡片**：嵌在编辑器右侧，可折叠/展开
- **转换按钮**：触发 LLM 调用（`NlToSimpletsConverter` / `SimpletsToNlConverter`）
- 本地 UI 嵌入通过 **前端 MCP Client** 与 `orule-server` 通信

### 4.9.3 切换开关同步逻辑

```
用户切换视图
     │
     ▼
读取当前 rule_version（code_semantic）
     │
     ├── 切到 SimpleTS 视图 → 直接显示 code_semantic
     ├── 切到 NL 视图       → 调用 NlToSimpletsConverter（LLM_BASED，SimpleTS → NL）
     ├── 切到表格视图       → 调用 SimpletsToTableConverter（AST_TREE，SimpleTS → Table）
     └── 切到 JSON 视图     → 只读显示 ts_ast（TS-AST JSON，调试用，不作为主编辑视图）

> **架构约束（ADR-009）**：所有切换都**以 SimpleTS 为中心**，不存在 NL ↔ Table 直接切换。
```

## 4.11 推进到第 5 轮的输入

| 输入项 | 值 |
|--------|-----|
| 元数据域 | `DomainType` / `ObjectType` / `AttributeType` / `EnumType` / `FunctionLib` / `RuleForm` |
| 规则域 | `RuleSet` / `Rule` / `RuleVersion` / `RuleArtifact` / `RuleSetArtifact` / `RuleTestCase` |
| 执行域 | `Execution` / `ExecutionLog`（append-only，不删除） |
| 运行时实例域 | `ObjectInst`（运行时对象实例，不落库）/ `RuleExecutor`（规则执行器） |
| 编译产物 | **落库**（`rule_artifact.compiled_code`） |
| 多版本 | 每保存一次升 version，历史永久保留 |
| 软删除 | `rule_set` / `rule` 软删；`rule_version` / `execution` 不允许删除 |
| Skill 层 | 无独立服务；前端 MCP Client + LLM；Skill UI 卡片嵌入编辑器 |
| 视图同步 | **以 SimpleTS 为中心**的星型结构（NL ↔ SimpleTS / Table ↔ SimpleTS / TS-AST & Groovy 只读） |
| Flyway | 5 个 migration（V1-V5），三 DB 共用 |
| `owner_code` 校验 | **强制校验** ObjectType 存在 |
| `artifact_uri` | 存**相对 URL**；由 `ArtifactStorage` 接口解析（默认本地文件系统，可替换 S3/OSS/MinIO，ADR-010） |
| `code1..code5` | 保持占位；`DomainType.RuleForm` 配置决定启用哪些字段 |
| `RuleSetArtifact` | **MVP 需要做** |
| `concurrency` | 批量执行并发度，默认 1（顺序）；-1 全并行（ADR-010） |
| `storage_type` / `storage_key` | 制品存储后端类型 + 物理 key（ADR-010） |
