## 2.2 角色（Actor）定义

| 编号 | 角色 | 主要场景 | 工具 |
|------|------|----------|------|
| **A1** | **业务分析师** | 用自然语言/表格写规则、查看执行日志、调试规则 | 规则管理后台（Web UI）+ 本地 Skill |
| **A2** | **规则管理员** | 管理领域元数据、CRUD 规则、管理版本、配置函数库 | 规则管理后台（Web UI） |
| **A3** | **AI Agent** | 通过自然语言生成规则、通过 MCP 调用执行、读取规则详情 | MCP Server |
| **A4** | **后端开发者** | 嵌入式集成到业务系统、调用 SDK 执行规则 | 嵌入式 SDK（Java）+ REST API |

> **MVP 权限策略**：A1 + A2 = 全部 CRUD 权限，不做精细 RBAC。A3/A4 = 调用方身份，无后台管理权限。详见 [ADR-006]（后续补）。

### P0 · 端到端核心链路（必须跑通）

| ID | 用例 | 主参与者 | 关键场景 | 验收口径 |

| **UC-02** | **表格形态编辑规则** | A1 | 在表格 UI 中编辑决策表 → 保存为规则 | 一个完整的折扣规则可在表格中编辑 |

| **UC-04** | **Groovy 执行器执行规则** | A1 / A3 | 输入事实 → 选择引擎 → 拿到执行结果 + 决策日志 | 一条规则在 Groovy 引擎执行成功 |

## 2.4 核心用例流程（详细）

### UC-01：自然语言生成规则（端到端核心）

**场景**：业务分析师想加一条"VIP 客户满 200 减 30"的订单折扣规则，但不想写代码。

```
┌────────────┐    ┌──────────┐    ┌────────────┐    ┌────────────┐
│ 业务分析师  │    │  Cursor  │    │ 本地 Skill │    │ orule MCP  │
│ (A1)       │    │ (A3)     │    │ (Local)    │    │ Server     │
└─────┬──────┘    └─────┬────┘    └──────┬─────┘    └──────┬─────┘
      │ 1.NL 输入        │                │                 │
      │  "VIP 满 200 减 30"               │                 │
      ├──────────────────▶                │                 │
      │                  │ 2.调用本地 skill                │
      │                  │  (entity_recognize)             │
      │                  ├───────────────▶                 │
      │                  │                │ 3.识别实体      │
      │                  │                │  客户=VIP       │
      │                  │                │  金额=200       │
      │                  │                │  动作=减30      │
      │                  │ 4.实体结果     │                 │
      │                  │◀───────────────┤                 │
      │                  │                │ 5.调用LLM转DSL  │
      │                  │                │  (标准规则生成) │
      │                  │                │                 │
      │ 6.Agent展示预览   │ ◀────── 7.返回TS-AST ────┐      │
      │◀─────────────────┤                        │      │
      │ 8.确认保存       │                        │      │
      ├─────────────────▶                        │      │
      │                  │ 9.通过MCP保存规则  ────┴─────▶
      │                  │                        │      │
      │                  │                        │ 10. 落库
      │                  │                        │      │
      │ 11.展示成功       │ ◀── 12.返回RuleID ─────┴──────┤
      │◀─────────────────┤                        │      │
```

**步骤说明**：

1. **A1 NL 输入**：在 Cursor 中用自然语言描述规则
2. **A3 调度本地 Skill**：Cursor 调用本地 Skill 工具 `orule_entity_recognize`
3. **本地 Skill 识别实体**：结合当前领域元数据（订单领域），识别客户/金额/动作等
4. **本地 Skill 返回实体结果**
5. **本地 Skill 调用 LLM**：调用"标准化规则生成" Skill，把实体+NL 转为 TS-AST
6. **A1 预览确认**：Agent 把生成的 TS-AST 渲染成自然语言让用户确认
7. **A1 确认保存**
8. **A3 通过 MCP 提交**：调用 `rule_create_from_nl` MCP 工具
9. **MCP Server 校验领域元数据、保存规则、生成 RuleID**
10. **落库到 MySQL/PostgreSQL**
11. **A1 收到成功提示**

## 2.6 边界场景与异常处理

| 场景 | 异常 | 处理策略 |
|------|------|----------|
| NL 输入含糊 | LLM 无法生成 TS-AST | 返回错误 + 建议补充信息 |
| 元数据未配置 | Agent 调用时领域不存在 | 阻止保存，提示先配置元数据 |
| 跨引擎切换失败 | Groovy 规则无法编译为 cruleengine 规则 | 返回错误，保留当前规则形态 |
| 本地 Skill 未启动 | Agent 调用本地工具失败 | 提示下载安装，提供降级到纯云端方案 |
| LLM 调用超时 | 网络或 API 限流 | 提示重试，保留输入草稿 |
| cruleengine 不可达 | SPI 适配器调用失败 | 降级到 Groovy 执行器，标记日志 |
| 数据库切换 | MySQL 切换到 PostgreSQL 时 schema 不兼容 | Flyway 迁移脚本需保证两库一致性 |

## 2.8 推进到第 3 轮的输入

第 2 轮确认的核心输入：

- **MVP 演示场景**：订单折扣 + CPQ 配置（orule 自有最小化模型，cruleengine 纯作执行引擎接入）
- **核心链路**：NL → TS-AST → 保存 → 多形态查看 → 双引擎执行（Groovy + cruleengine 适配）
- **MCP 工具集核心**：rule_create_from_nl、rule_list、rule_get、rule_execute
- **元数据基准**：orule 自有最小订单模型（订单/产品/客户/价格/折扣），不绑 cruleengine 元数据
- **角色权限**：A1+A2 = 全权限，A3/A4 = 调用方
- **状态机**：不做，保存即生效
- **优先级重排**：UC-11（LLM 转换器）从 P1 调整为 P0（UC-01 必走子步骤）
- **本地 Skill**：P0，不降级；纯云端 Skill 不作为兜底路径
