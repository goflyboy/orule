# ADR-001：系统命名为 orule，定位"AI 时代的开放规则底座"

- 状态：已接受
- 日期：2026-09-10
- 决策人：架构组
- 相关章节：01-边界与目标

## 背景

需要为新规则系统确定名称与一句话定位，作为后续所有文档、API、部署的统一前缀。

## 候选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| A：**orule**（open rule） | 简洁、好记；呼应"开放"的差异点；前缀清晰 | "orule" 可能被误读为 o-rule/i-rule |
| B：AI-RuleHub | 直接体现"AI 消费规则"，定位清晰 | 名字较长，不利于包名/域名 |
| C：RuleSystem | 通用、未体现差异化 | 过于通用，无语义指向 |

## 决策

采用方案 A：**orule**。"open" 强调表示/执行解耦的可扩展理念。

## 后果

- 正面影响：包名、API 路径、Docker 镜像名一致（前缀 `orule`）；语义指向清晰。
- 负面影响 / 成本：需在入门文档解释命名由来。
- 回退方案：保留 B 方案做别名；模块名改为 `open-rule-system` 不影响业务逻辑。
