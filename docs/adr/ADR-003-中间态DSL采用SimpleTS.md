# ADR-003：语义层中间态 = SimpleTS（TS-AST 仅作运行期 IR）

> 状态：**已更新**（2026-09-11 第 6 轮修正）
> 原版本日期：2026-09-10
> 决策者：架构组
> 相关：ADR-006、ADR-009、03-逻辑视图、04-数据模型、05-技术模型、06-运行视图

---

## 决策

> ⚠️ **本 ADR 在第 6 轮被修正**：原版本把 TS-AST 当作"中间态 DSL"，**这是错误的**。
> 修正后：**SimpleTS 是唯一的语义层中间态**，TS-AST 仅作为运行期 IR（编译内部产物）。

**双层模型（修正版）**：

```
┌──────────────────────────────────────────────────────────────┐
│  语义层中间态（面向业务/工程师，对外可见）                          │
│  ┌────────────────────────────────────────────┐              │
│  │         SimpleTS 源码（TS 安全子集）         │              │
│  └────────────────────────────────────────────┘              │
│                       │ 编译                                  │
│                       ▼                                       │
│  运行期 IR（内部表示，对外不可见）                                │
│  ┌────────────────────────────────────────────┐              │
│  │  SimpleTS-AST → TS-AST → 多引擎代码        │              │
│  └────────────────────────────────────────────┘              │
└──────────────────────────────────────────────────────────────┘
```

| 层 | 表示 | 角色 | 可见性 |
|----|------|------|--------|
| **语义层中间态** | **SimpleTS** | 业务/工程师写规则的"源语言" | **对外可见**（用户编辑器、LLM 转换的输入输出） |
| 内部表示 | SimpleTS-AST | 解析产物，语法树 + 位置信息 | 对外不可见 |
| 运行期 IR | TS-AST | 编译产物，多引擎 codegen 输入 | 对外不可见 |
| 执行产物 | Groovy / DRL / Python | 最终执行代码 | 落 RuleArtifact |

---

## 原因

1. **业务人员写规则的认知负担**
   - TS-AST 是 JSON 结构，对业务人员**写规则**门槛太高
   - LLM 直出 TS-AST 容易出错（节点结构复杂）

2. **SimpleTS 解决"开发期"体验**
   - 看起来像 TypeScript，但语法受限（白名单剪枝）
   - 业务人员可以读懂、可以手写
   - LLM 也能稳定生成

3. **TS-AST 保留"运行期"优势**
   - 多引擎代码生成（Groovy / DRL / Python）
   - 决策日志、行号追溯、Schema 校验

4. **本次修正的触发原因（用户决策）**
   - 原 ADR-003 把 TS-AST 描述为"中间态 DSL"，导致整个架构（包括运行视图、转换器插件）出现"两两互转"错误理解
   - 用户明确约束：**SimpleTS = 语义层中间态**（面向业务、面向 LLM），TS-AST = 运行期 IR（仅内部编译用）

```
                      ┌─────────────────┐
                      │    SimpleTS     │ ← 唯一的语义层中间态
                      │   （语义 DSL）    │
                      └────────┬────────┘
                               │
            ┌──────────────────┼──────────────────┐
            │                  │                  │
            ▼                  ▼                  ▼
      用户视图（3 种）       用户视图（1 种）       执行态（N 种）
       ┌─────────┐          ┌─────────┐       ┌─────────┐
       │   NL    │          │ Table   │       │ Groovy  │
       └─────────┘          └─────────┘       │  DRL    │
                                              └─────────┘
```

**只读调试视图（不参与转换）**：
- TS-AST JSON（SimpleTS 的编译内部产物）
- Groovy 源码（RuleArtifact.compiledCode 落库版本）

## 原始决策（保留历史记录）

> 以下是原版本决策内容，仅供追溯。本 ADR 已被修正版取代。

### 原决策（2026-09-10）

"一种语义、多种表现形态"需要中间态表示层。ADR-003 早期版本定义了 **TS-AST 作为单一中间态**，但实际开发中暴露出：
- TS-AST 是结构化 JSON，对业务人员/工程师**写规则**的认知负担偏高
- LLM 直出 TS-AST 易错、不稳定

### 原方案（已被取代）

```
NL / UI / 表格 → TS-AST → 多引擎代码
                (中间态)
```

**双层结构（原版）**：
1. **TS-AST（中间态）** = 业务规则语义
2. **多引擎代码**（Groovy / DRL / Python）= 执行形态

### 原备选方案（已存档）

| 备选 | 优点 | 缺点 |
|------|------|------|
| A：**SimpleTS + TS-AST 双层**（最终采纳并修正） | 人写源码、机器跑 AST；LLM 生成稳定；编译期拦截风险 | 需 SimpleTS 编译器骨架 |
| B：纯 TS-AST（被取代） | 单层简单 | 业务人员写不出；LLM 不稳定 |
| C：通用 JS/TS | 灵活 | 表达力过强，副作用多 |
| D：DMN/FEEL | 标准化 | 与 TS-AST 体系脱节；学习成本高 |
