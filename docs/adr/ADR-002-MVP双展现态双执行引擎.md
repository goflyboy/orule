# ADR-002：MVP 包含 NL + Table 双展现态；Groovy + cruleengine 双执行引擎

- 状态：已接受
- 日期：2026-09-10
- 决策人：架构组
- 相关章节：01-边界与目标 §1.4.1

## 背景

MVP 需要在 3 周内交付"端到端跑通"的 POC。决策者明确要求**不裁剪功能**：两种展现态 + 两种执行引擎全部进 MVP。

## 候选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| A：MVP 双展现态 + 双执行引擎 | 满足差异化卖点；为未来扩展做样板；与元数据形态配置深度绑定 | 3 周完成 = 高风险 [推断 高] |
| B：MVP 单展现态 + 单执行引擎 | 风险低、易交付 | 与"多形态"核心卖点不符，演示价值低 |
| C：MVP 双展现态 + 单执行引擎 | 中庸 | 错过 cruleengine 首批客户的快速整合 |

## 决策

采用方案 A：MVP 同时包含 NL + Table 双展现态、Groovy + cruleengine 双执行引擎。

**配套要求**：
- Groovy 执行器作为"开箱即用"默认，无需额外配置
- cruleengine 通过 SPI 插件方式接入，1 个示例领域（如订单）跑通
- 转换器在两种展现态之间通过 TS-AST 中间态互通

## 后果

- 正面影响：完整兑现"一种语义、多种形态"卖点；为后续 Drools/OR-Tools 等扩展铺路。
- 负面影响 / 成本：3 周内交付压力大，需两人 W2 起全栈并行；cruleengine 适配器是 W2 关键路径。
- 回退方案：若 W2 周末 Groovy/cruleengine 双引擎未跑通，MVP 退化到单 Groovy 执行器，cruleengine 留到 W4。
