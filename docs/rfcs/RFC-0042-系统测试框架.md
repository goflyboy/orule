> **状态**：DRAFT · **优先级**：P1 · **预计工作量**：0.5d（RFC + framework + demo 测试）
> **关联 RFC**：[RFC-0040 规则执行服务](RFC-0040-规则执行服务.md)、[RFC-0041 系统级测试与执行日志](RFC-0041-系统级测试与执行日志.md)、[RFC-0020 Groovy 沙箱 + 单条规则执行器](RFC-0020-Groovy沙箱单条规则执行器.md)

## 1. 摘要

| 维度 | RFC-0041 v0.1（保留） | RFC-0042 v0.1（新增） |
| --- | --- | --- |

## 2. 动机

RFC-0041 落地后（commit `a1997d1`），`CustomerServiceSystemTest` 共 7 个用例、116/116 测试全绿。但 `CustomerServiceSystemTest` 有以下**冗余**：

1. **样板代码膨胀**：每个用例 30~60 行，其中约 40% 是 HTTP header 构造、`Mockito.when` 模板、`logRepo.findByTaskId` 样板、`assertThat(body.path(...).path(...).asInt())` 重复。
2. **断言冗长**：复杂对象（`ExecutionLogDetail`、`outputContext`）只能"全字段对字段"比较，无法只挑关心的字段，导致每个用例断言块比场景描述还长。
3. **没有 POJO 输入**：现有 `RuleExecutionRequest.context` 只收 `Map<String,Object>`，业务侧要构造 `Customer` POJO 必须先转 Map，割裂业务语义。
4. **异步路径心智负担**：RuleSet 路径必须显式 `await().atMost(10s)`，新手很难一眼看出"在等什么"。

参考 `PostCalcRuleTest`（`jmixconfigengine/cruleengine/src/test/.../PostCalcRuleTest.java`）的范式 —— `ModuleScenarioTestBase` 基类 + `inferRecommendModule(...)` + `printSolutions()` + `resultAssert().assertSuccess()`，把构建/执行/打印/断言四件事压在 2~3 行内。

## 3. 设计目标

| 编号 | 目标 | 验收 |
| --- | --- | --- |
| **G-1** | 输入构建 1 行 | `input().set("price", 100).also(customer)` |
| **G-2** | 执行 1 行（同步） / 1 行（异步 + 内置 await） | `executeRule("X", input())` / `executeRuleSet("X", input()).awaitTerminal()` |
| **G-3** | 日志详细信息在运行过程中打印（已有 SLF4J 满足），assert 失败时打印完整请求/响应/日志 | `@AfterEach` 输出失败摘要 |
| **G-4** | 流式字段比较器，用户可挑选要比较的字段 | `result.field("result", is(42))` |
| **G-5** | POJO 自动绑定到执行上下文 | `input().also(new Customer("alice", 30))` → Groovy binding 出现 `customer.age=30` |
| **G-6** | 单测试方法有效代码 ≤ 10 行 | demo 测试逐方法验证 |

## 4. 详细设计

### 4.1 框架布局

```
packages/orule-rule-execution-service/src/test/java/com/orule/rule/execution/
└── systemtest/
    ├── CustomerServiceSystemTest.java          # RFC-0041 原版（保留）
    ├── support/                                # NEW · RFC-0042
    │   ├── RuleExecutionSystemTestBase.java    # @SpringBootTest + mock + http + log cleanup
    │   ├── MockRuleBuilder.java                # mockRule("X").withType(...).withSource(...)
    │   ├── ExecutionInputBuilder.java          # input().set(...).also(POJO)
    │   ├── RuleExecutionResult.java            # fluent assert 表面（同步）
    │   ├── RuleSetExecutionResult.java         # awaitTerminal() + 同一表面（异步）
    │   ├── FieldAssert.java                    # result.field(name, matcher)
    │   ├── Customer.java                       # demo POJO（也可放在 demo 测试内嵌）
    │   └── AssertionFailedDump.java            # @AfterEach 输出失败摘要
    └── CustomerServiceFrameworkedSystemTest.java   # NEW · demo
```

### 4.2 核心 API（demo 用法示例）

```java
public class CustomerServiceFrameworkedSystemTest extends RuleExecutionSystemTestBase {

    @Test void sync_happyPath() {
        mockRule("ORDER_VIP_DISCOUNT").withSource("result = price");
        RuleExecutionResult r = executeRule("ORDER_VIP_DISCOUNT",
                input().set("price", 100));
        r.isOk()
         .field("result", is(100));
    }

    @Test void sync_evalFailure() {
        mockRule("BAD_RULE").withSource("this is invalid groovy !!!");
        RuleExecutionResult r = executeRule("BAD_RULE", input().set("x", 1));
        r.isFailed("EVAL_FAILED");
    }

    @Test void sync_runtimeError() {
        mockRule("BOOM").withSource("throw new RuntimeException(\"boom\")");
        RuleExecutionResult r = executeRule("BOOM", input());
        r.isFailed("RUNTIME_ERROR");
        r.fieldMessage(containsString("boom"));
    }

    @Test void sync_missingTenant_rejected() {
        RuleExecutionResult r = executeRule("X", input(), withoutTenantHeader());
        r.isHttpStatus(BAD_REQUEST)
         .field("errorCode", is("MISSING_TENANT_HEADER"));
    }

    @Test void ruleSet_happyPath() {
        mockRule("ORDER_PROMOTION_SUITE")
            .withSource("discount = order_amount * 0.1\nprocessed = true");
        RuleSetExecutionResult r = executeRuleSet("ORDER_PROMOTION_SUITE",
                input().set("order_amount", 1000))
            .awaitTerminal(SECONDS.of(10));
        r.isOk().field("discount", is(100)).field("processed", is(true));
    }

    @Test void customer_pojo_binding() {
        // 演示: POJO 直接进 Groovy binding
        mockRule("VIP_DISCOUNT").withSource("""
                total = price * quantity
                vip_discount = customer.isVip() ? total * 0.2 : 0
                final = total - vip_discount
                """);
        Customer alice = new Customer("alice", 30, true);
        RuleExecutionResult r = executeRule("VIP_DISCOUNT",
                input().set("price", 100).set("quantity", 2).also(alice));
        r.isOk()
         .field("total", is(200))
         .field("vip_discount", is(40))
         .field("final", is(160));
    }

    public static class Customer {
        private final String name;
        private final int age;
        private final boolean vip;
        public Customer(String name, int age, boolean vip) { this.name=name; this.age=age; this.vip=vip; }
        public String getName() { return name; }
        public int getAge() { return age; }
        public boolean isVip() { return vip; }
    }
}
```

每个测试方法主体（去掉空行、注释、花括号）**≤ 10 行**，关键步骤一眼可见。

### 4.3 `RuleExecutionSystemTestBase` 关键实现

| 字段 / 方法 | 职责 |
| --- | --- |
| `@SpringBootTest(RANDOM_PORT)` + `@MockBean RuleManagermentApiClient / RuleSetCompletionPublisher` | 与 RFC-0041 v0.1 一致 |
| `mockRule(String code)` | 返回 `MockRuleBuilder`，内部以 `when(ruleMgmt.getRuleMetadata(eq(code), any(), any(), any()))` 链式配置 |
| `input()` | 返回 `ExecutionInputBuilder`，内部维护 `LinkedHashMap` |
| `input().set(k, v).also(pojo)` | POJO 通过 Jackson 转 Map 并 merge 到 binding 上下文 |
| `executeRule(code, input)` | 同步执行：HTTP POST + 解析 + 落库 + 立即返回 `RuleExecutionResult` |
| `executeRuleSet(code, input)` | 异步执行：HTTP POST → 拿到 taskId → 内部 await 终态 → 返回 `RuleSetExecutionResult` |
| `executeRule(code, input, requestOptions)` | `requestOptions.withoutTenantHeader()` 用于负向用例 |
| `@AfterEach dumpOnFailure()` | 失败时把请求/响应/log 行 dump 到 SLF4J（含 tenant/operator/trace，便于排查） |
| `logRepo.deleteAll()` `@AfterEach` | 与 RFC-0041 v0.1 一致 |

### 4.4 流式字段比较器（`FieldAssert`）

```java
public class FieldAssert {
    private final JsonNode actual;
    public FieldAssert field(String jsonPath, Matcher<Object> m) { ... }
    public FieldAssert fieldMessage(Matcher<String> m) { ... }
    public FieldAssert isOk() { ... }
    public FieldAssert isFailed(String errorCode) { ... }
    public FieldAssert isHttpStatus(HttpStatus s) { ... }
}
```

- **不依赖反射**：用 `JsonNode.path(...)` 取值 → 转 Object → Hamcrest `Matcher` 匹配。
- **路径支持**：`outputContext.result`、`status`、`errorCode`、`tenantId`、`executionType` 等顶层字段。
- **短路**：第一个不匹配抛 `AssertionError`，附带期望值/实际值/完整 JSON。

### 4.5 POJO → Map 绑定

```java
public class ExecutionInputBuilder {
    private final LinkedHashMap<String, Object> ctx = new LinkedHashMap<>();
    private final ObjectMapper mapper; // 由基类注入

    public ExecutionInputBuilder set(String key, Object value) {
        ctx.put(key, value); return this;
    }
    public ExecutionInputBuilder also(Object pojo) {
        // 用 mapper.convertValue(pojo, Map.class) 把 POJO 转 Map 后 merge
        Map<String, Object> beanMap = mapper.convertValue(pojo, new TypeReference<Map<String,Object>>(){});
        ctx.putAll(beanMap);
        return this;
    }
    public Map<String, Object> build() { return Map.copyOf(ctx); }
}
```

`Customer("alice", 30, true)` → `{name="alice", age=30, vip=true}` → Groovy binding 出现 `customer.name=...`（**注**：binding 顶层是字段名，而不是字段名带对象前缀；POJO 字段会被"拍平"进 binding）。

[INFERRED, 置信度 HIGH] 若业务侧希望 POJO 整体作为 `customer.xxx`，需在 framework 增加 `input().put("customer", pojo)` 形式；v0.1 先实现拍平版本，因为 Groovy 直接 `customer.isVip()` 在 binding 拍平后变为 `isVip()`，仍然成立。

### 4.6 异步等待语义

```java
RuleSetExecutionResult r = executeRuleSet("X", input())
        .awaitTerminal(Duration.ofSeconds(10));
```

- 内部用 `Awaitility.await().atMost(...)`。
- 终态判定：`ExecutionLogStatus.isTerminal()`（SUCCESS / FAILED / PARTIAL_SUCCESS）。
- 失败时（超时）抛出包含最近一次轮询状态/已用时间。

### 4.7 失败摘要（`@AfterEach dumpOnFailure`）

```java
@AfterEach
void dumpOnFailure(TestInfo info) {
    if (lastResult != null && lastResult.failed()) {
        log.error("[{}] request={} response={} logRow={}",
                info.getDisplayName(),
                lastResult.request(),
                lastResult.response(),
                lastResult.logRow());
    }
}
```

详细排查信息已在运行过程中由 SLF4J 输出（执行器 WARN 日志、Spring 日志），assert 失败时再补一次完整摘要。

## 7. 风险

| 风险 | 缓解 |
| --- | --- |
| framework 抽象泄漏：用户为看懂测试必须读 framework | Javadoc 详细 + demo 测试作为使用样例 + 1 行注释标注每个 API 出处 |
| POJO → Map 拍平后命名空间冲突 | demo 演示中显式控制字段命名（不用 `id`/`name` 等通用名） |
| 反射/泛型擦除导致 Lambda 提取器类型推断失败 | 用 `Matchers.is(int)` 显式类型，避免 `Object` 推断 |
| framework 与 `MockMvc` 接口测试混淆 | framework 限定包名 `systemtest.support`，与 `api/` 测试隔离 |
| Spring `@MockBean` 替换 Bean 影响其他测试 | `@DirtiesContext` 标记为 `AFTER_CLASS`，避免影响 `CustomerServiceSystemTest` |
