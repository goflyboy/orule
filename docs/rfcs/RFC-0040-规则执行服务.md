# RFC-0040: 规则执行服务（Rule/RuleSet Execution Service）

> **状态**：DRAFT · **优先级**：P0 · **预计工作量**：10d · **阶段**：S5
> **关联 RFC**：[RFC-0020 Groovy 沙箱 + 单条规则执行器](RFC-0020-Groovy沙箱单条规则执行器.md)、[RFC-0021 批量规则执行 + RuleSetArtifact](RFC-0021-批量规则执行RuleSetArtifact.md)、[RFC-0033 元数据管理 2 — RuleSetType 与 RuleType](RFC-0033-元数据管理2-RuleSetType与RuleType.md)、[RFC-0027 可观测性](RFC-0027-可观测性日志TraceActuator.md)

---

## 1. 摘要

设计并实现 `rule-execution-service`：作为 orule 平台对外提供规则执行的统一入口，对内承接 RFC-0020（单条规则 Groovy 沙箱）与 RFC-0021（规则集批量执行）。

- **同步入口**：`POST /api/v1/rule-executions`（单条规则，结果立即返回 + taskId）
- **异步入口**：`POST /api/v1/rule-set-executions`（规则集，立即返回 taskId，后台异步执行）
- **异步查询**：`GET  /api/v1/rule-set-executions/{taskId}`（查询规则集执行结果）
- **日志查询**：`GET  /api/v1/executions/{taskId}/logs`（查询执行详细日志）

执行结果统一落 `execution_log` 表，并发完成事件通过 Kafka 通知上游。

---

## 2. 动机

- **当前缺口**：RFC-0020 / RFC-0021 仅定义"执行器内部行为"，缺少对外 HTTP 契约、Feign 客户端抽象、执行日志持久化、异步结果查询接口。
- **业务诉求**：CustomerService 等上游业务需要统一入口，避免每个业务方各自实现"调用 Feign → 包装结果 → 落库"逻辑。
- **可观测需求**：所有规则执行必须留痕（taskId、耗时、输入输出 context、错误信息），便于审计与排障（依据 RFC-0027）。

```sql
    finished_at     DATETIME(3),
```

**JavaSourceExecutor 核心逻辑**（包装 RFC-0020）：

```java
public class JavaSourceExecutor implements RuleExecutor {

    private final GroovyShellFactory shellFactory;

    @Override
    public String executorType() { return "java-source"; }

    @Override
    public ExecutionOutput execute(ExecutionInput input) {
        String javaSource = wrapAsJavaMainMethod(input.sourceCode(), input.context());

        GroovyShell shell = shellFactory.create();
        Script script;
        try {
            script = shell.parse(javaSource);
            input.context().forEach((k, v) -> script.setProperty(k, toJavaObject(v)));
            script.run();
        } catch (CompilationFailedException | RuntimeException e) {
            throw new RuleExecutionException("EVAL_FAILED", e.getMessage(), e);
        }

        Map<String, ObjectInst> output = extractContextFromScript(script);
        return new ExecutionOutput(output, true, null, null);
    }

    private String wrapAsJavaMainMethod(String ruleBody, Map<String, ObjectInst> ctx) {
        return SourceTemplate.wrap("RuleScript", ctx.keySet(), ruleBody);
    }
}
```

### 3.11 Service 实现

```java
@Service
public class DefaultRuleSetExecutorService implements RuleSetExecutorService {

    @Override
    @Transactional
    public RuleSetExecutionSubmitResponse submit(RuleSetExecutionRequest req) {
        RuleSetArtifact artifact = ruleMgrClient.getRuleSetArtifact(req.ruleSetCode());
        if (artifact == null) throw new RuleSetNotFoundException(req.ruleSetCode());

        String taskId = UUID.randomUUID().toString();
        int total = artifact.rules().size();
        ExecutionLog log = ExecutionLog.pending(taskId, RULE_SET, req.ruleSetCode(),
            artifact.executorType(), req.context(), total);
        executionLogRepository.save(log);

        taskDispatcher.dispatch(taskId, req, artifact);

        return new RuleSetExecutionSubmitResponse(taskId, "PENDING");
    }

    @Override
    public RuleSetExecutionResultResponse queryResult(String taskId) {
        ExecutionLog log = executionLogRepository.findByTaskId(taskId)
            .orElseThrow(() -> new TaskNotFoundException(taskId));
        return RuleSetExecutionResultResponse.from(log);
    }
}
```

### 3.12 RuleSetExecutor 后台 Worker

```java
@Component
public class DefaultRuleSetExecutor implements RuleSetExecutor {

    @Override
    @Async("ruleSetExecutorPool")
    public void run(String taskId, RuleSetExecutionRequest req, RuleSetArtifact artifact) {
        ExecutionLog log = executionLogRepository.findByTaskId(taskId).orElseThrow();
        log.markRunning();
        executionLogRepository.save(log);

        Map<String, ObjectInst> context = req.context();
        int success = 0, failed = 0;
        String errorMsg = null;

        try {
            for (RuleRef ref : artifact.rules()) {
                RuleArtifact rule = ruleMgrClient.getRule(ref.ruleCode());
                RuleExecutor executor = executorRegistry.resolve(rule.executorType());

                ExecutionInput input = new ExecutionInput(
                    rule.executorType(), rule.sourceCode(), context, rule.metadata());
                ExecutionOutput output = executor.execute(input);
                context = output.context();
                success++;
            }
            log.markSuccess(context, success, failed);
        } catch (Exception e) {
            failed = artifact.rules().size() - success;
            errorMsg = e.getMessage();
            log.markFailed(errorMsg, success, failed);
        }
        executionLogRepository.save(log);

        kafkaTemplate.send("rule-set-execution-completed",
            new RuleSetExecutionCompletedEvent(taskId, log.status(),
                log.totalCount(), success, failed, log.durationMs()));
    }
}
```

### 3.13 错误处理

| 错误场景 | 处理策略 | HTTP / 错误码 |
|---------|---------|--------------|
| `ruleCode` 不存在 | Feign 404 → 抛 RuleNotFoundException | 404 / `RULE_NOT_FOUND` |
| `ruleSetCode` 不存在 | 同上 | 404 / `RULE_SET_NOT_FOUND` |
| ExecutorType 未注册 | ExecutorRegistry 抛 ExecutorNotFoundException | 500 / `EXECUTOR_NOT_REGISTERED` |
| 规则代码编译失败 | GroovyShell 抛 CompilationFailedException | 200 / `success=false, errorCode=EVAL_FAILED` |
| 规则运行时异常 | catch RuntimeException，记录日志 | 200 / `success=false, errorCode=RUNTIME_ERROR` |
| RuleSet 部分规则失败 | 继续执行剩余规则，标记 failedCount | taskId 完成事件 status=PARTIAL_SUCCESS |
| 异步任务超时 | Spring @Async 配置超时 → 标记 FAILED | Kafka 事件 status=FAILED |

## 4. 技术决策（ADR）

### ADR-001：执行引擎选择 — GroovyShell vs GraalVM

**决策**：默认 JavaSourceExecutor 使用 GroovyShell，预留 GraalVM 扩展点（PythonExecutor 样例实现）。

| 维度 | GroovyShell ✅ | GraalVM |
|------|---------------|---------|
| 启动延迟 | <10ms | 200-500ms |
| 资源占用 | 共享 JVM | 独立 isolate |
| 安全沙箱 | SecureASTCustomizer 限制 import/receiver | native-image 隔离（强） |
| 内存隔离 | ❌ 共享进程 | ✅ TruffleLanguage 隔离 |
| 多语言 | 仅 Java/Groovy | Python/JS/Ruby |

**风险与缓解**：
- 共享 JVM 内存 → GroovyClassLoader 隔离 + SecureASTCustomizer 黑名单 `Runtime/Process/Reflection`
- 反射逃逸 → 默认禁用 `Method.invoke`，需要时由执行器显式启用
- 性能 → 类缓存：`GroovyShell.parse()` 编译结果按 `sourceCodeHash` 缓存，下次直接复用

### ADR-002：Rule/RuleSet 接口分离

**决策**：分离接口（`RuleExecutor` / `RuleSetExecutor`），通过 `ExecutorRegistry` 各自注册。

**理由**：
- 同步 vs 异步语义不同
- 元数据形状不同
- 错误处理粒度不同

### ADR-003：执行日志存储 — 单表 vs 分表

**决策**：单表 `execution_log`，通过 `execution_type` 字段区分。

**风险与缓解**：
- 表膨胀 → 按月分区（PARTITION BY RANGE），3 个月前数据归档到冷库
- 高写入延迟 → JSON 字段（input_context/output_context）考虑压缩存储或外链对象存储

### ADR-004：异步执行模型 — 进程内 @Async vs 消息队列

**决策**：默认 Spring `@Async`（进程内线程池），预留 MQ 扩展。

**演进路径**：
- v1：Spring @Async + 进程内 ThreadPoolTaskExecutor
- v2：引入 Kafka + 持久化任务表（重启后恢复）

### ADR-005：Feign 客户端命名

**决策**：使用 `RuleManagermentApiClient`（保留用户指定拼写）。

> ℹ️ 拼写问题建议在 PR 描述中说明（如需后续纠正为 `RuleManagement`，可发起单独 RFC）。

## 8. 安全考虑

1. **多租户隔离**：
   - RuleArtifact 增加 `tenantId` 字段，Feign 客户端透传 `X-Tenant-Id` 头

   - execution_log 表记录 `operator_id`（来自 JWT）
   - Kafka 完成事件含 `operator_id`，便于审计

4. **限流**：
   - 按 `ruleCode` 维度限流（Guava RateLimiter）：防止单条规则被恶意刷爆
   - 按租户维度限流：默认 100 TPS/租户

## 12. 决策落地说明（Q1~Q4 实现细节）

本节针对 §11 中已确认的 4 个决策，补充具体实现约束与代码细节。

### 13.1 Q1：RuleSet 部分失败不回滚

**决策**：规则集中任意一条规则执行失败，**已经成功执行的规则对 context 的修改将保留**，不进行事务回滚。

**实现约束**：

```java
// §3.12 DefaultRuleSetExecutor.run() — 失败后状态标记
} catch (Exception e) {
    failed = artifact.rules().size() - success;
    errorMsg = e.getMessage();
    // ✅ 不回滚 context，保留已成功执行的累积变更
    // ✅ status 标记为 PARTIAL_SUCCESS（区分全成功 SUCCESS）
    log.markPartialSuccess(context, success, failed, errorMsg);
}
```

**业务侧补偿契约**：
- Kafka 事件 `rule-set-execution-completed` 中 `status=PARTIAL_SUCCESS`，业务方可订阅事件触发补偿
- `GET /api/v1/rule-set-executions/{taskId}` 返回的 `outputContext` 是**部分执行后的中间状态**，业务方应结合 `successCount` / `failedCount` 判断是否可用
- 日志表 `execution_log.output_context` 持久化部分结果，便于事后排查

**测试要求**：
- 规则集 3 条规则中第 2 条失败 → 断言 `successCount=1, failedCount=1, outputContext` 含规则 1 的修改

### 13.2 Q2：ObjectInst 覆盖属性（深拷贝 + 原址修改）

**决策**：执行器对 context 中 ObjectInst 的修改采用**原址修改**（in-place mutation），但执行器内部必须**先深拷贝输入 context**，避免污染上游调用方。

**实现约束**：

```java
// ExecutionInput 构造：调用方先深拷贝 context
ExecutionInput input = new ExecutionInput(
    rule.executorType(),
    rule.sourceCode(),
    deepCopyContext(req.context()),     // ✅ 深拷贝入口 context
    rule.metadata()
);

// JavaSourceExecutor 内部：从 GroovyShell 反射读出的 ObjectInst 共享副本内存
// 修改副本不影响原始对象（Groovy setProperty 操作的是脚本局部引用副本）
ExecutionOutput output = new ExecutionOutput(
    deepCopyContext(scriptContext),     // ✅ 输出时再深拷贝一次，保证调用方拿到的也是独立副本
    true, null, null
);
```

**深拷贝实现**：

```java
public class ObjectInstDeepCopier {
    public static Map<String, ObjectInst> copy(Map<String, ObjectInst> ctx) {
        Map<String, ObjectInst> copy = new HashMap<>(ctx.size());
        ctx.forEach((k, v) -> copy.put(k, deepCopy(v)));
        return copy;
    }

    private static ObjectInst deepCopy(ObjectInst orig) {
        ObjectInst c = new ObjectInst(orig.typeCode());
        orig.attributes().forEach((k, v) -> c.setAttribute(k, copyValue(v)));
        return c;
    }

    private static Object copyValue(Object v) {
        if (v instanceof ObjectInst) return deepCopy((ObjectInst) v);
        if (v instanceof Collection) return ((Collection<?>) v).stream()
                .map(ObjectInstDeepCopier::copyValue).collect(Collectors.toList());
        if (v instanceof Map) { /* 递归 */ }
        return v;   // String / Number / Boolean 不可变，直接共享
    }
}
```

**SimpleTS 语义对齐**：
- SimpleTS 中的 `order.discount = 30` 是**引用赋值 + 属性修改**，与本决策一致
- 业务方传入 `context` → 执行器修改副本 → 返回新副本，**对原始入参零副作用**

### 13.3 Q3：v1 进程内 LRU 缓存

**决策**：GroovyShell 编译结果（`Script` 对象）使用 **Caffeine LRU 缓存**，最大 1000 条，按 `sourceCodeHash` 索引。

**实现约束**：

```java
@Component
public class GroovyClassCache {

    private final Cache<String, Script> cache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterAccess(Duration.ofMinutes(10))
        .recordStats()
        .build();

    public Script getOrCompile(String javaSource, GroovyShell shell) {
        String hash = Hashing.sha256()
            .hashString(javaSource, StandardCharsets.UTF_8)
            .toString();
        return cache.get(hash, k -> shell.parse(javaSource));
    }

    public CacheStats stats() {
        return cache.stats();
    }
}
```

**可观测性**：
- Micrometer 指标 `groovy.class.cache.hit.rate` / `groovy.class.cache.size` / `groovy.class.cache.evictions`
- 缓存命中率低于 70% 告警（可能存在规则频繁变更）

**演进路径**：
- v1：进程内 Caffeine（单实例有效）
- v2：评估 Redis（多实例共享 + 持久化），但需评估序列化开销
- v2 决策点：当集群实例数 ≥ 5 且规则代码量大（>10MB）时启动 Redis 评估

### 13.4 Q4：当前分离，v2 抽象 AbstractExecutor

**决策**：v1 保持 `RuleExecutor` 与 `RuleSetExecutor` 接口分离，仅在共享组件（`ExecutorRegistry` / `ExecutionInput` / `ExecutionOutput`）做收敛。

**v1 共享抽象边界**：

```java
// 仅共享执行上下文与执行结果模型
public interface Execution<I extends ExecutionInput, O extends ExecutionOutput> {
    String executorType();
    O execute(I input);
}

// v1 不强制 RuleExecutor / RuleSetExecutor 实现同一接口
// 但所有 Executor 必须实现 executorType() 与 execute(...) 语义契约
```

**v2 抽象计划**：
```java
// v2 演进：抽象出 AbstractExecutor
public abstract class AbstractExecutor<I, O> implements Execution<I, O> {
    protected void preCheck(I input) { /* 公共前置校验 */ }
    protected void postHandle(O output) { /* 公共后置处理（埋点/日志）*/ }
}

// RuleExecutor / RuleSetExecutor 各自继承 AbstractExecutor
```

**v1 不抽象的理由**：
- Rule 同步 / RuleSet 异步，行为差异大
- 抽象过早会引入不必要的耦合
- 业务方当前对分离接口无负面反馈

**v2 触发条件**：
- RuleExecutor 与 RuleSetExecutor 出现 ≥ 3 个共同的前置/后置逻辑
- 或新增第三种执行器（如 BatchRuleExecutor）时

### 16.6 错误码速查表

| HTTP | errorCode | 含义 | 建议处理 |
|------|-----------|------|---------|
| 200 | — | success=true，正常返回 | — |
| 200 | `EVAL_FAILED` | 规则代码编译/运行异常 | 检查规则代码/SDK 白名单 |
| 200 | `RUNTIME_ERROR` | 规则执行时异常 | 检查规则逻辑/输入数据 |
| 404 | `RULE_NOT_FOUND` | 规则编码不存在 | 校对 ruleCode |
| 404 | `RULE_SET_NOT_FOUND` | 规则集编码不存在 | 校对 ruleSetCode |
| 404 | `TASK_NOT_FOUND` | taskId 不存在 | 校对 taskId（可能过期归档） |
| 429 | `RATE_LIMIT_EXCEEDED` | 触发限流 | 降频重试或申请配额 |
| 500 | `EXECUTOR_NOT_REGISTERED` | executorType 未注册 | 排查 SPI 注册 |

#### 异步调用 + 回调示例

```java
@Service
public class PromotionService {

    @Autowired
    private RuleExecutionClient ruleClient;

    public CompletableFuture<PromotionResult> applyPromotion(PromotionContext ctx) {
        Map<String, ObjectInst> context = toContext(ctx);
        RuleSetExecutionRequest req = new RuleSetExecutionRequest("ORDER_PROMOTION_SUITE", context);

        // 1. 提交异步任务
        RuleSetExecutionSubmitResponse submit = ruleClient.submitRuleSet(req);
        String taskId = submit.taskId();
        log.info("Submitted async task: taskId={}", taskId);

        // 2. 轮询结果（指数退避）
        return pollResult(taskId, Duration.ofMillis(100), Duration.ofSeconds(10));
    }

    private CompletableFuture<PromotionResult> pollResult(String taskId, Duration initial, Duration max) {
        return CompletableFuture.supplyAsync(() -> {
            Duration delay = initial;
            while (true) {
                RuleSetExecutionResultResponse r = ruleClient.queryRuleSetResult(taskId);
                if ("PENDING".equals(r.status()) || "RUNNING".equals(r.status())) {
                    sleep(delay);
                    delay = delay.multipliedBy(2).compareTo(max) > 0 ? max : delay.multipliedBy(2);
                    continue;
                }
                return toResult(r);
            }
        }, executor);
    }

    // 3. Kafka 回调（推荐用于生产环境）
    @KafkaListener(topics = "rule-set-execution-completed")
    public void onCompleted(RuleSetCompletedEvent event) {
        if ("PARTIAL_SUCCESS".equals(event.status())) {
            compensationService.trigger(event);
        }
    }
}
```

#### 响应类型定义

```typescript
export interface RuleExecutionResponse {
  taskId: string;
  success: boolean;
  outputContext: Record<string, ObjectInst>;
  executedAt: string;          // ISO 8601
  durationMs: number;
  errorCode: string | null;
  errorMessage: string | null;
}

export interface RuleSetExecutionSubmitResponse {
  taskId: string;
  status: 'PENDING';
}

export type RuleSetStatus =
  | 'PENDING'
  | 'RUNNING'
  | 'SUCCESS'
  | 'FAILED'
  | 'PARTIAL_SUCCESS';

export interface RuleSetExecutionResultResponse {
  taskId: string;
  status: RuleSetStatus;
  startedAt: string | null;
  finishedAt: string | null;
  durationMs: number | null;
  totalCount: number | null;
  successCount: number | null;
  failedCount: number | null;
  outputContext: Record<string, ObjectInst> | null;
  errorMessage: string | null;
}

export class RuleExecutionError extends Error {
  constructor(
    public errorCode: string,
    public errorMessage: string,
    public taskId?: string,
  ) {
    super(`[${errorCode}] ${errorMessage}`);
    this.name = 'RuleExecutionError';
  }
}
```

#### React Hook 示例（前端可视化测试用例）

```typescript
import { useState, useCallback } from 'react';
import { RuleExecutionClient, RuleExecutionError } from '@orule/rule-execution-client';

export function useRuleExecution() {
  const [loading, setLoading] = useState(false);
  const [result, setResult] = useState<RuleExecutionResponse | null>(null);
  const [error, setError] = useState<RuleExecutionError | null>(null);

  const execute = useCallback(async (req: RuleExecutionRequest) => {
    setLoading(true);
    setError(null);
    try {
      const resp = await client.executeRule(req);
      setResult(resp);
      return resp;
    } catch (e) {
      const err = e instanceof RuleExecutionError ? e : new RuleExecutionError('UNKNOWN', String(e));
      setError(err);
      throw err;
    } finally {
      setLoading(false);
    }
  }, []);

  return { execute, loading, result, error };
}

// 在测试用例页面使用
function TestCaseRunner({ ruleCode, context }: { ruleCode: string; context: any }) {
  const { execute, loading, result, error } = useRuleExecution();

  const onRun = async () => {
    await execute({ ruleCode, context });
  };

  return (
    <div>
      <Button onClick={onRun} loading={loading}>运行</Button>
      {result && <pre>{JSON.stringify(result.outputContext, null, 2)}</pre>}
      {error && <Alert type="error">{error.errorCode}: {error.errorMessage}</Alert>}
    </div>
  );
}
```

### 17.3 SDK 设计原则

| 原则 | 体现 |
|------|------|
| **零样板（Zero Boilerplate）** | 自动装配 / 自动 Header 注入 / 轮询内置 |
| **类型安全（Type-Safe）** | Java Record + TS Interface，DTO 严格对齐 |
| **可观测（Observable）** | Micrometer 透传 / 客户端日志含 taskId + traceId |
| **容错（Fault-Tolerant）** | 轮询超时 / 重试 / 熔断（Resilience4j） |
| **业务友好（Business-Friendly）** | ObjectInst ↔ 业务对象自动转换（`toObjectInst` / `fromObjectInst`） |
| **生态对齐（Eco-Aligned）** | Java 走 Spring Boot Starter；TS 走 axios + React Hook |
