运行视图描述系统在运行时（runtime）的行为，包括：

1. **关键业务流程**：规则从自然语言到执行的完整链路

## 6.1 关键业务流程

### 6.1.1 流程一：规则从自然语言到执行（完整链路）

```
业务人员（NL）
    │
    │ Step 1：打开 RuleEditor，输入自然语言描述
    │ Endpoint: N/A（纯前端操作）
    ▼
orule-web 前端（RuleEditor 组件）
    │
    │ Step 2：点击 "LLM 转换" 按钮
    │ 调用：<iframe> orule-llm-studio Local Server
    │ POST /api/v1/convert/nl-to-simplets
    ▼
orule-llm-studio（Electron）
    │
    │ Step 3：Electron Main Process 调用 Cursor/OpenCode MCP
    │ IPC channel: llm:chat
    ▼
Cursor / OpenCode（本地 Agent，MCP Server）
    │
    │ Step 4：返回 SimpleTS 源码
    ▼
orule-web 前端（RuleEditor 组件）
    │
    │ Step 5：用户确认 SimpleTS，点击 "保存"
    │ POST /api/v1/rulesets/{code}/rules/{code}
    │ body: { codeSemantic: "SimpleTS 源码" }
    ▼
orule-server（RuleService）
    │
    │ Step 6：版本快照（自动 + 手动）
    │ 新建 RuleVersion（type=MAINTENANCE, codeSemantic 已填充）
    ▼
orule-server（SimpleTSParser，GraalJS）
    │
    │ Step 7：编译 SimpleTS → TS-AST
    │ parse(source: String, domainMeta: DomainMeta): TSSNode
    ▼
orule-server（GroovyCodeGen）
    │
    │ Step 8：TS-AST → Groovy 源码
    │ toGroovy(ast: TSSNode): String
    ▼
orule-server（RuleArtifactService）
    │
    │ Step 9：发布制品
    │ 新建 RuleArtifact（engineType=GROOVY, compiledCode=Groovy源码）
    ▼
orule-server（RuleSetArtifactService）
    │
    │ Step 10：发布规则集（可选）
    │ RuleSetArtifact = RuleSet + N 个 RuleArtifact 打包
    ▼
orule-server → orule-runtime
    │
    │ Step 11：通知执行（异步 HTTP POST /api/v1/runtime/execute）
    │ body: { ruleId, version, facts: [...] }
    ▼
orule-runtime（ExecutionService）
    │
    │ Step 12：ArtifactLoader 从 orule-server 拉取 RuleArtifact
    ▼
orule-runtime（GroovySandboxExecutor）
    │
    │ Step 13：沙箱执行 Groovy 脚本
    │ GroovySandbox.execute(compiledCode, facts, whitelist)
    ▼
orule-runtime（ExecutionRepository）
    │
    │ Step 14：写入 Execution + ExecutionLog
    ▼
orule-runtime → orule-server（回调）
    │
    │ Step 15：执行结果回传（可选，HTTP 回调）
    ▼
orule-web 前端（ExecutionLog 页面）
    │
    │ Step 16：轮询 /api/v1/runtime/executions/{id}
    ▼
业务人员看到执行结果
```

### 6.1.2 流程二：规则集批量执行

```
业务人员（RuleSetList 页面）
    │
    │ 点击 "执行规则集"
    │ POST /api/v1/rulesets/{code}/execute
    ▼
orule-server
    │
    │ 加载 RuleSetArtifact
    │ 提取关联的 RuleArtifact 列表
    ▼
orule-server → orule-runtime（批量）
    │
    │ POST /api/v1/runtime/batch-execute
    │ body: { artifacts: [{ ruleId, version, facts }] }
    ▼
orule-runtime（批量执行）
    │
    │ 按规则集顺序依次执行（可配置并发度）
    │ 写入 Execution 记录
    ▼
orule-runtime → orule-server（汇总结果）
    │
    │ 返回批量执行结果（每个规则的 ExecutionResult）
    ▼
orule-web 前端
    │
    │ 展示批量执行汇总（成功 / 失败 / 超时）
```

### 6.1.3 流程三：四视图双向同步

```
RuleEditor 组件内部，四个视图两两同步：

    SimpleTS 源码
          ↕ 编译（orule-server）
    TS-AST JSON
          ↕ 代码生成（orule-server）
    自然语言描述（NL）
          ↕ 语义抽象（orule-server）
    表格（Table）

同步规则：
- 任意视图编辑 → 其他视图被动刷新（显示最新内容）
- 用户确认后才写入 Rule（不自动保存）
- 视图切换保留编辑状态（内存缓存）
- TS-AST JSON 为标准中间态，其他视图都以其为基准
```

## 6.2 状态机

### 6.2.1 规则制品生命周期

```
    ┌──────────────────────────────────────────────────────────────────┐
    │                       规则制品生命周期                            │
    └──────────────────────────────────────────────────────────────────┘

    ┌──────────────┐
    │  MAINTENANCE │  ← 维护态（RuleVersion.type）
    │  （草稿）     │    · 规则正在编辑，未发布
    └──────┬───────┘    · codeSemantic / code1..N 可编辑
           │            · 不会生成 RuleArtifact
           │ save()
           │ publish()
           ▼
    ┌──────────────┐
    │   PUBLISHED  │  ← 发布态
    │  （已发布）   │    · RuleArtifact 已生成
    └──────┬───────┘    · compiledCode 已锁定
           │            · 可被 orule-runtime 加载执行
           │ newVersion()
           │ retract()
           ▼
    ┌──────────────┐
    │   RETIRED    │  ← 废弃态
    │  （已废弃）   │    · 不再被 orule-runtime 加载
    └──────────────┘    · 历史 Execution 记录保留
```

### 6.2.2 执行状态机

```
    ┌──────────────┐
    │   PENDING    │  ← 等待执行
    │              │    · 已入队，等待 orule-runtime 调度
    └──────┬───────┘
           │ orule-runtime 接受
           ▼
    ┌──────────────┐
    │   RUNNING    │  ← 执行中
    │              │    · GroovySandboxExecutor 正在执行
    └──────┬───────┘
           │
     ┌─────┴─────┐
     │           │
     ▼           ▼
┌────────┐  ┌──────────┐
│SUCCESS │  │ FAILED   │  ← 终态
│（成功）│  │（失败）   │
└────────┘  └──────────┘
     │           │
     │           │ 原因写入 ExecutionLog.errorStack
     │           │ errorCode 枚举：TIMEOUT / SANDBOX_VIOLATION / GROOVY_ERROR / UNKNOWN
     ▼           ▼
┌────────────────────────────────────┐
│         FINAL (不可变更)            │
└────────────────────────────────────┘

异常路径：
- 超时（orule-runtime.timeout=30s）：→ FAILED, errorCode=TIMEOUT
- 沙箱违规：→ FAILED, errorCode=SANDBOX_VIOLATION
- Groovy 运行时异常：→ FAILED, errorCode=GROOVY_ERROR
```

### 6.2.3 规则集制品状态

```
    ┌──────────────┐
    │   DRAFT      │  ← 草稿
    │  （未打包）   │    · 规则集下有 PUBLISHED 规则，但未打包
    └──────┬───────┘
           │ package()
           ▼
    ┌──────────────┐
    │  PUBLISHED   │  ← 已发布
    │  （已打包）   │    · RuleSetArtifact 已生成
    └──────┬───────┘    · artifactUri 指向制品文件
           │ newVersion()
           │ suspend()
           ▼
    ┌──────────────┐
    │  SUSPENDED   │  ← 已暂停
    │  （已暂停）   │    · 不参与批量执行
    └──────────────┘    · 历史 Execution 记录保留
```

## 6.3 并发与事务边界

### 6.3.1 服务内事务（Spring @Transactional）

| Service | 事务边界 | 说明 |
|---------|----------|------|
| `RuleService` | 单 Rule 原子操作 | 单条规则保存/发布在同一事务内 |
| `RuleSetArtifactService` | 打包原子操作 | RuleSetArtifact 创建 + 关联 RuleArtifact 在同一事务 |
| `ExecutionService`（runtime） | 单次执行 | facts 解析 → 沙箱执行 → 结果写入，原子操作 |

### 6.3.2 跨服务事务（最终一致性）

> **原则**：`orule-server` 与 `orule-runtime` 之间**无分布式事务**，采用**异步补偿 + 幂等重试**。

```
场景：orule-server 发布 RuleArtifact，orule-runtime 执行

Step 1：orule-server 发布制品（本地事务 → 提交）
Step 2：orule-server 异步通知 orule-runtime（HTTP POST）
Step 3：orule-runtime 接收，执行（本地事务 → 提交）

失败处理：
· Step 2 失败：orule-server 本地记录待发送消息，重试（N 次，指数退避）
· Step 3 失败：orule-runtime 记录 ExecutionStatus=PENDING，重试
· Step 3 执行结果回传失败：Execution 已写入 DB，orule-server 轮询补偿
```

### 6.3.3 并发控制

| 场景 | 控制方式 | 说明 |
|------|----------|------|
| 同一 Rule 多版本并发编辑 | 乐观锁（`@Version`） | JPA 乐观锁，并发写入抛出 `OptimisticLockException` |
| 规则集批量执行 | 规则集级别分布式锁 | `SETNX ruleset:{code}:lock`（Redis）或 DB 行锁 |
| SimpleTS 编译（GraalJS） | 编译器单例 + 读锁 | GraalJS Context 可复用，编译过程加读锁 |
| Groovy 沙箱执行 | 线程池隔离 | `orule-runtime` 维护线程池（core=4, max=16），每个执行一个线程 |
| Artifact 拉取 | 缓存 + 版本校验 | `orule-runtime` 内存缓存 Artifact（TTL=5min），ETag 校验 |

## 6.4 错误处理与回退

### 6.4.1 各层级错误处理策略

```
┌─────────────────────────────────────────────────────────────────┐
│  层级         │  错误类型              │  处理策略                │
├───────────────┼───────────────────────┼─────────────────────────┤
│  orule-web    │  REST 调用 4xx/5xx     │  Ant Design Message 提示  │
│  前端         │  网络断开              │  离线缓存（localStorage）  │

│  orule-server │  SimpleTS 语法错误      │  返回错误行号 + 提示        │

│               │  Groovy 代码生成失败     │  记录 TS-AST，返回生成错误  │

│  orule-runtime│  Groovy 运行时异常       │  ExecutionResult.FAILED   │

│               │  执行超时（30s）         │  ExecutionResult.TIMEOUT   │
│               │  规则不存在             │  HTTP 404                 │
│               │  Artifact 拉取失败       │  重试 3 次，指数退避        │
└───────────────┴───────────────────────┴─────────────────────────┘
```

### 6.4.3 沙箱异常处理

```java
// orule-runtime/infrastructure/sandbox/GroovySandboxExecutor.java
public ExecutionResult execute(String groovyCode, Map<String, Object> facts) {
    try {
        Object result = sandbox.run(groovyCode, new Binding(facts));
        return ExecutionResult.success(result);
    } catch (SecurityException e) {
        // 沙箱违规（白名单外方法调用）
        return ExecutionResult.failure(
            "SANDBOX_VIOLATION",
            "不允许的方法调用：" + e.getMessage(),
            e
        );
    } catch (org.codehaus.groovy.runtime.InvokerInvocationException e) {
        // Groovy 运行时异常
        return ExecutionResult.failure(
            "GROOVY_ERROR",
            extractCause(e),
            e
        );
    } catch (Exception e) {
        // 其他异常
        return ExecutionResult.failure("UNKNOWN", e.getMessage(), e);
    }
}
```

### 6.4.4 降级策略

| 场景 | 降级行为 | 恢复方式 |
|------|----------|----------|
| orule-runtime 不可用 | 编译成功但不触发执行；Execution 状态为 PENDING | runtime 恢复后轮询重试 |
| SimpleTS 编译失败 | 阻断发布；Rule 保持 MAINTENANCE | 用户修正 SimpleTS 后重试 |
| orule-llm-studio 不可用 | LLM 转换按钮置灰；提示"LLM Studio 未启动" | 启动 Electron 后恢复 |
| GraalJS 编译器崩溃 | JVM 重启 orule-server | 健康检查 + 自动重启 |

## 6.6 安全运行时策略

### 6.6.1 Groovy 沙箱白名单（完整版）

```java
// orule-runtime/infrastructure/sandbox/SimpleTSGroovyWhitelist.java
// 白名单来源：SimpleTS §8.1 函数库 + §7 操作符
public class SimpleTSGroovyWhitelist extends org.kohsuke.groovy.sandbox.impl.InterceptorScope {

    // §8.1 函数库（Math / String / Date / Array）
    private static final Set<String> ALLOWED_METHODS = Set.of(
        // Math
        "abs", "min", "max", "floor", "ceil", "round",
        "pow", "sqrt", "log", "sin", "cos", "tan",
        // String
        "length", "charAt", "substring", "indexOf", "lastIndexOf",
        "startsWith", "endsWith", "contains", "trim",
        "toUpperCase", "toLowerCase", "replace", "split",
        // Date
        "getFullYear", "getMonth", "getDate", "getHours", "getMinutes",
        "getSeconds", "getTime", "now",
        // Array
        "size", "getAt", "add", "remove", "contains",
        "sort", "join", "collect", "findAll", "sum"
    );

    // 允许的类静态访问
    private static final Set<String> ALLOWED_CLASSES = Set.of(
        "Math", "String", "Integer", "Double", "Boolean",
        "BigDecimal", "java.time.LocalDate", "java.time.LocalDateTime"
    );

    @Override
    public Object onMethodCall(Invoker invoker, Object receiver, String method, Object... args)
            throws Throwable {
        // 白名单校验
        if (!ALLOWED_METHODS.contains(method)) {
            throw new SecurityException(
                "不允许的方法调用 '" + method + "'（不在 SimpleTS 白名单）\n" +
                "如需新方法，请在 DomainType.FunctionLib 中申请。"
            );
        }
        return invoker.onMethodCall(receiver, method, args);
    }

    @Override
    public Object onStaticCall(Invoker invoker, Class receiver, String method, Object... args)
            throws Throwable {
        if (!ALLOWED_CLASSES.contains(receiver.getSimpleName())) {
            throw new SecurityException(
                "不允许的类访问 '" + receiver.getSimpleName() + "'"
            );
        }
        return invoker.onStaticCall(receiver, method, args);
    }

    @Override
    public Object onNewInstance(Invoker invoker, Class receiver, Object... args) throws Throwable {
        // 禁止 new 任意对象（防止 RCE）
        throw new SecurityException("禁止在规则脚本中实例化对象");
    }
}
```

### 6.6.2 执行超时

```java
// orule-runtime/application/ExecutionService.java
@Service
public class ExecutionService {
    @Value("${orule.execution.timeout-ms:30000}")
    private long executionTimeoutMs;

    public ExecutionResult execute(ExecutionRequest req) {
        Future<ExecutionResult> future = executorService.submit(() -> {
            return groovySandboxExecutor.execute(req.getCompiledCode(), req.getFacts());
        });

        try {
            return future.get(executionTimeoutMs, TimeUnit.MILLISECONDS);
        } catch (TimeoutException e) {
            future.cancel(true);
            return ExecutionResult.timeout(executionTimeoutMs);
        }
    }
}
```

## 6.7 推进到第 7 轮的输入

| 输入项 | 值 |
|--------|-----|
| 核心流程 | NL→SimpleTS→TS-AST→Groovy→Execution（异步两阶段） |
| 状态机 | RuleVersion: MAINTENANCE→PUBLISHED→RETIRED；Execution: PENDING→RUNNING→SUCCESS/FAILED |
| 事务策略 | 服务内原子（@Transactional）；跨服务最终一致性（异步补偿+幂等重试） |
| 并发控制 | 乐观锁（JPA @Version）；规则集分布式锁；Groovy 线程池隔离 |
| 错误处理 | 编译错误行号内联；沙箱白名单；超时 30s；降级 PENDING |
| 可观测性 | JSON 日志（ELK）；traceId 全链路；Actuator 健康检查；Micrometer 指标 |
| 安全 | Groovy 白名单（ALLOWED_METHODS + ALLOWED_CLASSES）；禁止 new 对象；执行超时 |
