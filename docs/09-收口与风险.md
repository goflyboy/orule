## 9.0 本轮核心内容

收口与风险是 4+1 架构视图的最后一篇，承担以下职责：

1. **全局总览**：把 8 份视图压缩成一张图 + 一张表

3. **风险清单**：技术风险 / 业务风险 / 项目风险
4. **遗留问题**：所有未决 [OPEN] 问题集中归类
5. **MVP 范围与里程碑**：明确 MVP 必须做 / 二期做 / 三期做
6. **后续工作流**：从设计 → 实现的过渡（推荐 RFC-driven development）
7. **架构健康度自评**：一份给团队和管理者的体检表

### 9.3.1 MVP 范围（必须做）

|------|------|

## 9.4 风险清单

### 9.4.1 技术风险

| 编号 | 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|------|----------|
| **T1** | Groovy 沙箱被绕过 | 🔴 高 | 任意代码执行 | 白名单 + 多重校验；定期安全审计；CodeQL 扫描 |
| **T2** | LLM 输出幻觉导致错误规则 | 🔴 高 | 编译错误 / 运行时错误 | Schema 强制注入 + SimpleTS 校验；编译失败回退；测试用例验证 |
| **T3** | SimpleTS 解析器性能瓶颈 | 🟡 中 | 大规则集编译慢 | AST 缓存 + 增量编译；二三期考虑 ANTLR |
| **T4** | orule-server 单点故障 | 🟡 中 | 服务不可用 | MVP 接受；二期部署多副本 + 健康检查 |
| **T5** | 数据库迁移失败 | 🟡 中 | 启动失败 | Flyway 校验；迁移前自动备份 |
| **T6** | 本地一体化部署依赖复杂 | 🟡 中 | 新人上手难 | 一键启动脚本 + Docker Compose fallback |
| **T7** | SimpleTS 表达力不足 | 🟢 低 | 复杂规则无法表达 | 二期扩展（自定义函数 + 嵌套表达式） |
| **T8** | 并发执行导致线程池耗尽 | 🟢 低 | 规则执行慢 / 失败 | 限流 + 超时 + 监控告警 |

### 9.4.2 业务风险

| 编号 | 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|------|----------|
| **B1** | SimpleTS 接受度低 | 🟡 中 | 用户改用自然语言直接给 LLM | 渐进式推广；多视图编辑器降低门槛 |
| **B2** | 规则执行性能无法满足业务 | 🟡 中 | 大批量场景失败 | 二期引入 cruleengine；并行执行；缓存 |
| **B3** | LLM API 成本失控 | 🟡 中 | 月度预算超支 | Token 限额 + 计量统计；提示词压缩 |
| **B4** | 用户不理解 NL / SimpleTS / 表格的区别 | 🟢 低 | 误用 | 编辑器内置引导文档 + 视频教程 |

### 9.4.3 项目风险

| 编号 | 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|------|----------|
| **P1** | 架构文档与实现脱节 | 🔴 高 | 文档失效 | 强约束：架构变更必须先更新 ADR；PR 检查清单 |
| **P2** | 关键人员离职 | 🟡 中 | 知识断层 | ADR + RFC 文化；Code Review 必须 2 人 |
| **P3** | 工期延误 | 🟡 中 | MVP 不能按时交付 | MVP 范围严格控制；二期功能剥离 |
| **P4** | 技术债务累积 | 🟡 中 | 二期重构困难 | 定期重构；CI 强制检查；覆盖率基线 |
