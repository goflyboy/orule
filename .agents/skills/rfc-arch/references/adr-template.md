# ADR 模板（架构决策记录）

每轮关键决策产出一条 ADR，存入项目 ADR 目录（如 `docs/adr/`），按序号命名：`ADR-001-决策标题.md`。

## 模板

```markdown
# ADR-00X：决策标题

- 状态：已接受 / 已提议 / 已废弃
- 日期：YYYY-MM-DD
- 决策人：XXX
- 相关章节：[架构文档对应章节]

## 背景

这个决策解决什么问题？有什么约束？什么触发条件？

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A： |  |  |
| B： |  |  |
| C： |  |  |

## 决策

选择了哪个方案？具体内容是什么？

## 后果

- 正面影响：
- 负面影响 / 成本：
- 回退方案：
```

## 填写要点

- **背景**：写清楚"为什么现在要做这个决策"，避免三个月后看不懂。
- **候选方案**：至少 2 个，如实记录被否方案的优点，证明权衡过。
- **决策**：明确"选了 A 而不是 B"，理由要可追溯。
- **后果**：负面后果必须诚实写，不写等于没评估。

## 参考示例

```markdown
# ADR-003：产品数据存储采用关系库+图数据库混合架构

- 状态：已接受
- 日期：2026-08-01
- 决策人：Fibo
- 相关章节：4.6 技术模型

## 背景

产品数据需要同时满足企业治理（审批/版本/权限）和 Agent 多跳消费（配套关系/影响分析）。
单一存储无法同时满足两类需求。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A：纯关系库 | 治理成熟、团队熟悉 | 多跳查询困难、Agent 消费不自然 |
| B：纯图数据库 | 关系表达自然、多跳强 | 治理能力弱、批量导入不成熟 |
| C：关系库+图数据库混合 | 兼顾治理与语义消费 | 架构复杂、需解决同步一致 |

## 决策

采用方案 C：关系库为治理底座，图数据库承载语义网络，向量库承载文档召回。

## 后果

- 正面影响：治理与消费解耦，Agent 可做多跳扩展。
- 负面影响 / 成本：需建设事件驱动的同步链路和 ID 对齐机制。
- 回退方案：图库退化为主体数据的只读投影，关系库保留全部权威数据。
```
